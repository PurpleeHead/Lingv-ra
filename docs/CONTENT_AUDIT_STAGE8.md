# Lingvéra — аудит контента и надёжности подсказок

## Объём и способ проверки

- Проверен локальный источник A1: 30 уроков, 120 упражнений (`choice`, `text`, `word_order`). Slug не менялись.
- Все 120 ключей проверяются через тот же `_grade`, который использует API: все поддержанные варианты принимаются, контрольный неправильный ответ отклоняется. Для word order проверяются ID и перемешанный публичный порядок токенов.
- Проверены 120 подсказок уровня 1 и 120 уровня 2; каждая локализована на русском и английском — всего 480 текстов подсказок.
- Механический валидатор проверяет схему, обязательные переводы/подсказки, уникальность slug и упражнений, дубликаты, утечку полного ответа в подсказке и совпадение полного seeded-контента с JSON.
- Автоматические проверки не подтверждают грамматическую естественность и педагогическую последовательность на уровне квалифицированного преподавателя; замечания ниже — результат редакторского прохода, но курс всё ещё нуждается в финальной вычитке преподавателем английского.

## Диагностика прежнего 404

Путь `/api/v1/lessons/{lesson_slug}/exercises/{exercise_slug}/hints/{level}` зарегистрирован. Текущая база — `sqlite:///./lingvera.db`, миграция `0006_exercise_hints` применена; `daily-routine` доступен, а `routine-1` принадлежит этому уроку и содержит оба уровня подсказок. Точный запрос к работающему локальному API теперь возвращает HTTP 200.

Найденный конфигурационный дефект объясняет вероятное расхождение базы: `backend/.env.example` указывал `sqlite:///./lingualoop.db`, тогда как код по умолчанию, README и существующая база используют `sqlite:///./lingvera.db`. При использовании старого примера создавался бы другой пустой SQLite-файл; отсутствующий урок/упражнение безопасно возвращает 404. Пример и локальная команда README теперь согласованы с `lingvera.db`. Логи и тело исходного браузерного 404 недоступны, поэтому нельзя доказать, что именно этот сценарий вызвал прежнюю ошибку, а не устаревший процесс backend. Исходный сбой не воспроизводится на текущей конфигурации.

При отсутствии или неполноте сохранённого hint API возвращает `404 {"detail":"Hint not available"}`. Неизвестные и недоступные ресурсы также дают 404; неверный уровень — 422; отсутствие авторизации — 401. API не подменяет отсутствующую подсказку ответом.

Кроме пяти явных утечек, прежние подсказки повторяли одну и ту же общую фразу для несвязанных заданий и в заданиях выбора часто сразу называли правильный вариант. Все уровни переписаны по типу упражнения и правилу задания; второй уровень конкретнее первого, но не содержит полного ключа. Для отдельных закрытых грамматических вопросов он намеренно указывает правило, которое почти однозначно определяет форму.

Английские поля `instruction.en` теперь не содержат русских предложений. Русский источник в prompt для упражнений перевода оставлен русским намеренно: это сам материал задания, а не перевод интерфейса.

## API, безопасность и сохранность данных

- Подсказка возвращает только `exercise_id`, запрошенный `level` и локализованный `hint`. Ключи `correct`, `accepted`, `order` и `answer_data` в ответе отсутствуют.
- Публичный ответ урока не содержит закрытые подсказки или ключи ответа. Подсказки требуют ту же серверную авторизацию и проверяют опубликованность/доступность урока и принадлежность ему упражнения.
- Запрос подсказки не создаёт попытки, активность, завершение, словарные записи или изменение статистики; это покрыто интеграционным тестом.
- Новая миграция не потребовалась: аддитивная миграция `0006_exercise_hints` уже существует и соответствует ORM (`alembic check`).
- Перед повторным seed и после него совпали счётчики таблиц: users 1, user_settings 1, learning_events 16, lesson_progress 2, vocabulary_items 9, learning_activities 2, courses 1, lessons 30, exercises 120. Upsert не удаляет строки.

## Остаточные ограничения и ручная проверка

- Не проверены PostgreSQL, Docker Compose, Telegram и реальный Telegram WebView; Docker CLI в этой среде отсутствует.
- Обычная production-сборка Vite в Windows sandbox блокируется `EPERM` на `realpath` кириллического пути. Typecheck проходит; это не считается успешной сборкой.
- Не выполнен визуальный браузерный/мобильный просмотр. После запуска Mini App вручную проверить: (1) открыть `daily-routine` → `routine-1`; (2) убедиться, что подсказок нет до нажатия; (3) запросить уровни 1 и 2 по отдельности; (4) проверить отказ/повтор при отключённой сети; (5) перейти к следующему упражнению и убедиться, что старые подсказки очищены; (6) в английском интерфейсе проверить язык подсказки; (7) повторить на ширине 320 px и с клавиатурной навигацией; (8) убедиться, что попытка и прогресс изменяются только после отправки ответа.
- Преподавателю английского желательно отдельно проверить естественность английских объяснений/подсказок и точность терминов A1. Скриптовые проверки подтверждают структуру и отсутствие полных ключей, но не являются экспертизой преподавателя.
