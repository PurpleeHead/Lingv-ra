# Модель данных Lingvéra

## Таблицы

| Таблица | Назначение и связи |
|---|---|
| `users` | Telegram ID (unique), имя, дата создания. |
| `user_settings` | Настройки пользователя; unique FK `user_id` → `users`, каскадное удаление. Defaults `ru`, `en`, 10 минут; цель 5–60. |
| `courses` | Уникальный slug, локализованные title/description, исходный и изучаемый язык, CEFR level, порядок, опубликованность. |
| `lessons` | Уникальный slug, FK курса, локализованные заголовок/описание, тематическая лексика в JSON, порядок и доступность. Unique `(course_id, sort_order)`. |
| `exercises` | Уникальный slug, FK урока, тип `choice`/`text`/`word_order`, инструкция, prompt, публичные данные, закрытый ключ ответа и локализованные подсказки уровней 1/2 в отдельном JSON-поле. Unique `(lesson_id, sort_order)`. |
| `learning_events` | Каждая отправленная попытка: FK пользователя, lesson/exercise slug, ответ, корректность, время. Индекс по пользователю и времени. Оставлена совместимой с исходной миграцией. |
| `learning_activities` | Проверенные действия для дневной цели и серии: FK пользователя, UTC-дата, тип (`exercise`/`vocabulary_review`), ключ источника, UTC timestamp. Unique `(user_id, activity_date, activity_type, source_key)` предотвращает повторное начисление за один и тот же источник в тот же день. |
| `lesson_progress` | Уникальная запись завершения для `(user_id, lesson_id)`, оба FK с каскадным удалением; время завершения. Повторные попытки не дублируют завершение. |
| `vocabulary_items` | Личные слова и перевод; время следующего повтора, оценки/счётчики, серия успешных повторов, последний интервал и время, а также краткоживущее состояние раскрытия перевода. Индекс по пользователю и due time. |

Связи: `Course 1:N Lesson 1:N Exercise`; `User 1:1 UserSettings`, `User 1:N LearningEvent`, `User 1:N LearningActivity`, `User 1:N LessonProgress`; `Lesson 1:N LessonProgress`. Внешние ключи и уникальность обеспечиваются БД. Упражнения используют JSON для локализованных строк и type-specific структур. Их shape проверяется Pydantic-моделями перед seed-загрузкой. Клиент получает публичные поля задания; подсказка отдается отдельным запросом уровня и никогда не включается в обычный ответ урока.

`learning_events.exercise_id` намеренно остаётся slug-строкой без FK: поле было частью исходной схемы попыток, и добавление строгого FK/переименование потребовало бы преобразования уже сохранённых ответов. Новые course/lesson/exercise slug стабильны, поэтому для учебного API они служат публичными идентификаторами.

## Миграции и начальный контент

`0001_initial` — исходные пользователи, настройки, попытки и словарь. `0002_learning_engine` добавляет курсы, уроки, упражнения и прогресс, `0003_vocabulary_review_state` добавляет состояние повторов, `0004_lesson_vocabulary` добавляет словарь урока и nullable source key личного слова. Миграции не удаляют существующие строки; downgrade операций, которые могли бы удалить пользовательские данные, заблокирован.

`0005_learning_activity` создаёт аддитивную таблицу `learning_activities`, не backfill-ит историю. Дневная активность и streak доступны только начиная с этого релиза; предыдущие попытки и review-счётчики продолжают участвовать в общих lifetime-метриках. Все календарные дни рассчитываются в UTC до появления явной пользовательской timezone setting.

Начальный курс `backend/content/en_ru_a1.json` валидируется Pydantic и заполняется повторяемой командой `python -m app.seed_content`. Upsert по slug обновляет authored content и не удаляет строки отсутствующего из файла контента.

## Критерии завершения урока

Попытки сохраняются как append-only события. Урок считается завершённым, когда у конкретного пользователя существует хотя бы одна успешная попытка по каждому доступному упражнению; уникальный ключ `lesson_progress(user_id, lesson_id)` фиксирует завершение однократно. `GET /api/v1/progress` считает число правильных/неправильных ответов из event log.

## Ограничения MVP

Дневная цель измеряет уникальные правильные ответы по упражнению плюс принятые backend оценки повтора. Это количество подтверждённых действий, не продолжительность обучения. За день один и тот же slug упражнения учитывается один раз; оценка слова учитывается при реальном переносе `next_review_at`. Верная повторная отправка остаётся в журнале попыток. Уроки сохраняют текущий гибкий доступ: `is_next` — рекомендация, остальные доступные уроки не заблокированы.

Для слов реализован упрощённый прозрачный планировщик, а не полный SM-2. Новая миграция `0003_vocabulary_review_state` добавляет состояние к существующим личным словам с нулевым backfill и не удаляет/не перестраивает строки. Устарые записи сохраняют свой `next_review_at`.

Слова урока входят в личный словарь после завершения урока. Сидер не создаёт личные записи; завершённые до этой версии уроки получают слова при следующем запросе словаря/повторов. Уникальный индекс `(user_id, source_key)` делает копирование идемпотентным. История и расписание существующих слов остаются неизменными.

Планирование: Again — повтор через 10 минут, увеличивает счётчик ошибок и сбрасывает серию/интервал; Hard — 1 день для первой успешной оценки, затем `ceil(предыдущий интервал × 1.2)` (максимум 365 дней); Good — 2 дня, затем `ceil(интервал × 2)` (максимум 730); Easy — 4 дня, затем `ceil(интервал × 2.5)` (максимум 1095). Раздельные лимиты удерживают Easy длиннее Good даже после достижения предельных интервалов. Успешными считаются Hard/Good/Easy. Успешные/неуспешные счётчики и серия изменяются только на backend. Это детерминированная эвристика для MVP, не заявляется как соответствующая SM-2.
