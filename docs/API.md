# API Lingvéra (v1)

Защищённые маршруты требуют заголовок `X-Telegram-Init-Data` с исходным initData Mini Apps либо локальную dev identity только в development. Идентификатор пользователя вычисляет сервер. Контент выбирается только из опубликованного курса и доступных уроков/упражнений.

## Маршруты

| Метод и путь | Назначение |
|---|---|
| `GET /health`, `GET /ready` | Liveness и готовность БД/миграций. |
| `GET /api/v1/me`, `PATCH /api/v1/me/settings` | Профиль и личные настройки. |
| `GET /api/v1/courses` | Опубликованные курсы в порядке `sort_order`. |
| `GET /api/v1/courses/{course_slug}` | Описание опубликованного курса. |
| `GET /api/v1/courses/{course_slug}/lessons` | Доступные уроки по порядку с `completed` и единственным `is_next` для текущего пользователя. |
| `GET /api/v1/lessons` | Совместимый список уроков начального курса `english-a1`. |
| `GET /api/v1/lessons/{lesson_slug}` | Содержимое урока и публичные поля упражнений. |
| `POST /api/v1/lessons/{lesson_slug}/answer` | Проверка ответа и запись попытки. |
| `GET /api/v1/progress` | Сводка попыток и прогресс текущего пользователя. |
| `GET /api/v1/dashboard` | Серверная сводка курса, дневной цели, серии, 7 дней активности и раздельных метрик. |
| `GET /api/v1/progress/lessons` | Завершённые уроки с временем завершения. |
| `GET /api/v1/vocabulary` | Личный словарь для экрана словаря (включает переводы). |
| `GET /api/v1/review/due` | Due-слова текущего пользователя без переводов. Первый вызов создаёт личные копии стартовой лексики, если словарь пуст. |
| `GET /api/v1/vocabulary/{item_id}/translation` | Раскрывает перевод due-слова текущего пользователя; фиксирует факт раскрытия. |
| `POST /api/v1/vocabulary/{item_id}/review` | Сохраняет оценку и вычисленное сервером расписание. |

Пример `GET /api/v1/review/due` (перевода намеренно нет):

```json
[{"id": 15, "word": "hello", "next_review_at": "2026-10-12T05:00:00Z"}]
```

Клиент сначала запрашивает перевод только после нажатия «Показать перевод», затем отправляет одну из оценок:

```http
POST /api/v1/vocabulary/15/review
Content-Type: application/json
```

```json
{"rating":"good"}
```

Допустимые оценки: `again`, `hard`, `good`, `easy`. Ответ содержит личное расписание, например:

```json
{
  "id": 15,
  "word": "hello",
  "translation": "привет",
  "rating": "good",
  "successful_reviews": 1,
  "failed_reviews": 0,
  "consecutive_successes": 1,
  "interval_days": 2,
  "last_reviewed_at": "2026-10-12T05:00:00Z",
  "next_review_at": "2026-10-14T05:00:00Z"
}
```

Again планирует retry через 10 минут. Первая Hard/Good/Easy назначает 1/2/4 дня; повторные успешные оценки умножают предыдущий интервал на 1.2/2/2.5 соответственно с округлением вверх до суток и лимитами 365/730/1095 дней. Это MVP-эвристика, не полный SM-2. Раскрытие перевода обязательно до оценки. Недоступное/уже оценённое до следующего срока слово возвращает `409`; неизвестное или принадлежащее другому пользователю — `404`. Повторная оценка в той же сессии не меняет историю второй раз: после первой записи слово больше не due.

## Учебный контент

Текущий seed содержит 30 уроков и 120 упражнений A1. Все исходные lesson/exercise slug сохранены; каждый урок содержит четыре упражнения. Первая пятнадцатка сохраняет прежний порядок, новые темы продолжают курс: дом, транспорт, покупки, одежда, погода, профессии, предпочтения, способности, действия сейчас, предлоги, просьбы, диалоги, планы и итоговое повторение.

Заголовки и описание (цель/короткое пояснение) урока возвращаются локализованными объектами `{ "ru": "...", "en": "..." }`. `GET /api/v1/lessons/{slug}` включает поле `vocabulary` с тематическими словами и переводами; в личный словарь слова копируются после серверно подтверждённого завершения урока. Список упражнений отсортирован по `sort_order`. Публичный ответ не включает `answer_data`.

Типы ответов:

- `choice`: `{ "exercise_id": "hello-1", "answer": "hello" }`, где `answer` — ID одного из доступных вариантов.
- `text`: `{ "exercise_id": "hello-2", "answer": "Nice to meet you" }`. Ответ сравнивается с явно заданными вариантами после нормализации Unicode NFC, регистра и последовательностей пробелов. Акценты/диакритика и границы слов сохраняются.
- `word_order`: `{ "exercise_id": "about-2", "answer": ["t1", "t2", "t3", "t4"] }`; каждый опубликованный token ID должен присутствовать ровно один раз.

В `word_order` порядок токенов в `public_data.tokens` перемешан относительно правильного порядка. Клиент отправляет выбранную последовательность ID, backend проверяет её равенство закрытому `answer_data.order`; порядок отображения не является ключом ответа.

Валидация bundled-контента запускается из `backend`: `python -m app.validate_content`. После `alembic upgrade head` и `python -m app.seed_content` дополнительно сверьте связи в БД командой `python -m app.validate_content --check-db`.

Пример фрагмента `GET /api/v1/lessons/about-me`:

```json
{
  "id": "about-me",
  "course_id": "english-a1",
  "title": {"ru": "Расскажи о себе", "en": "Talk about yourself"},
  "level": "A1",
  "exercises": [{
    "id": "about-2",
    "type": "word_order",
    "prompt": {"ru": "Собери фразу «Я из России».", "en": "Build the sentence «Я из России»."},
    "tokens": [{"id": "t1", "text": "I"}, {"id": "t2", "text": "am"}]
  }]
}
```

Пример `POST /api/v1/lessons/hello-basics/answer`:

```json
{"exercise_id":"hello-1","answer":"hello"}
```

```json
{"correct":true,"correct_answer":"Hello","explanation":"Hello is a common greeting.","lesson_completed":false}
```

`lesson_completed` становится true после хотя бы одного правильного ответа на каждое доступное упражнение урока. Повторные ответы добавляют отдельные попытки в журнал, но завершение урока хранится с уникальным ключом (пользователь, урок).

## Ошибки

FastAPI использует единый формат `{ "detail": "..." }`: `401` — невалидная авторизация, `404` — отсутствующий/неопубликованный/чужой ресурс, `409` — слово не due или перевод не раскрыт, `422` — неверный формат/оценка, `503` — БД или миграция недоступны. Правильный ответ и пояснение доступны только после отправки ответа.

Подсказки выдаются отдельно авторизованному пользователю: `GET /api/v1/lessons/{lesson_slug}/exercises/{exercise_slug}/hints/{level}`, где `level` — `1` или `2`. Ответ: `{ "exercise_id": "hello-1", "level": 1, "hint": "..." }`; текст локализуется по `user.settings.ui_language`. Обычный ответ `GET /api/v1/lessons/{lesson_slug}` не включает подсказки или ключи проверки. Клиент запрашивает следующий уровень только по явному действию пользователя. Несвязанный с уроком exercise возвращает `404`, неверный уровень — `422`.

Проверка initData следует Telegram HMAC-SHA-256 алгоритму; `initDataUnsafe` и отдельно переданный Telegram ID не являются авторизацией.

## Dashboard и activity (Stage 6)

`GET /api/v1/dashboard` требует ту же серверную авторизацию и возвращает только агрегаты текущего пользователя. `today.total_actions` — сумма уникальных правильных упражнений и принятых оценок повторения за UTC-день. Неверная попытка не учитывается. Повтор правильного ответа по тому же упражнению в тот же UTC-день остаётся отдельной попыткой в `GET /progress`, но не увеличивает дневную цель повторно. Оценка повтора считается только если backend действительно изменил расписание; повторный запрос до следующего срока получает `409` и не считается.

`today.goal` — целое число действий из пользовательской настройки `daily_goal` (сохраняется через `PATCH /api/v1/me/settings`, диапазон 5–60 для совместимости с уже сохранёнными настройками; интерфейс предлагает 5/10/15). Это не минуты. Streak считает последовательные UTC-даты активности, заканчивая сегодня, если сегодня уже есть действие, иначе вчера; после пропуска серия равна нулю. `recent_activity` содержит семь UTC-дней, включая нулевые дни. Счётчики попыток, отправленных правильных ответов, уникальных правильно решённых упражнений, выученных уникальных слов и отправок повторения возвращаются раздельно.

Новая ежедневная история начинается с миграции `0005_learning_activity`; старые `learning_events` и агрегированные счётчики слов сохраняются, но прежние дни повторений восстановить нельзя. API фиксирует `timezone: "UTC"`; локальный часовой пояс клиента пока не хранится.
